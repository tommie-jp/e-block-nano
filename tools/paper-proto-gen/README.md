# paper-proto-gen — 紙プロトタイプの真上撮影写真ジェネレータ

認識パイプライン (四隅マーカー検出 → ホモグラフィ整流 → セル切り出し → タグデコード
→ ネットリスト) を、実物の紙を印刷・撮影する前に**合成画像**で検証するためのツール。
方式の全体像は [docs/recognition-pipeline.md](../../docs/recognition-pipeline.md) を参照。

第1弾は **Lチカ回路**。劣化シミュレーション (チルト・照明ムラ・ぼけ・ノイズ) は後回しで、
まずは**劣化なしの理想画像 (v0)** と**正解 JSON サイドカー**を出す。

## なぜ拡散モデルを使わないか

タグ (AprilTag / ArUco) はビット単位で正しくないと 1 個の誤読で回路図全体が嘘になる。
そのため生成モデルではなく **OpenCV の aruco で各タグを正確に描画**し、盤面レイアウト
どおりに合成する。「写真らしさ」が要るときは、この理想画像に後段で劣化を足す方針
(後日実装)。同じレンダラから 600dpi 印刷用画像も出せるので、実物紙プロトの印刷にも使える。

## 前提 (設計上の決定事項)

- 盤面 8×8、セルピッチ 10.16mm (4P)
- セルタグ: AprilTag 36h11 (`DICT_APRILTAG_36h11`)。タグ ID = 部品種のみ、**向きはタグの回転**
- 四隅フィデューシャル: 互いに異なる ID の ArUco 4x4_250 4 個 (セルタグと辞書を分けて誤検出回避)
- 解像度の既定は 20px/mm (保守値。実機は撮影 15-20cm で約 30px/mm)

## セットアップ

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

## 使い方

```bash
# Lチカ回路の理想画像 + 正解データを out/ に生成 (末尾でデコード疎通確認)
.venv/bin/python generate.py

# 解像度を変えてタグサイズ限界の当たりを付ける
.venv/bin/python generate.py --px-per-mm 12

# 別の回路を生成
.venv/bin/python generate.py --board circuits/xxx.board.json
```

出力 (`out/`, gitignore 済み):

- `<name>_ideal.png` — 劣化なしの真上視点画像
- `<name>_ideal.groundtruth.json` — 四隅マーカー座標・グリッド幾何・セルごとのタグ ID / 向き / 位置

## ファイル

| ファイル | 役割 |
| --- | --- |
| `generate.py` | 生成本体。盤面ファイルを読み、タグを合成し、正解データを書く |
| `tag_assignment.json` | 部品 ID ↔ タグ ID の**正準割当**。認識実装と共有する唯一の情報源 |
| `circuits/lchika.board.json` | Lチカの正解盤面 (e-block-nano version 1 形式。アプリでもそのまま開ける) |

## 向きの規約

`orientation` は時計回り (アプリの `rotateBlock` と同じ、0/90/180/270)。生成側はタグ画像を
`orientation` ぶん時計回りに回して貼る。認識側は逆変換で向きを復元する。

## 正解データ = アプリで開ける盤面

`circuits/*.board.json` は e-block-nano の versioned 盤面ファイルそのもので、アプリで
そのまま開ける。よって「生成画像の正解」と「アプリの盤面」が一致し、将来は
**認識結果 vs 盤面ファイル**の突き合わせがそのまま回帰テストになる。Lチカ盤面は
アプリの netlist ビルダで単一直列ループ (電池/抵抗/LED/スイッチ) になることを確認済み。

## 次のタスク (このツールのスコープ外)

1. 生成画像を OpenCV パイプライン (四隅検出 → 整流 → セル切り出し → デコード) に通し、
   正解データと照合して条件別の成功率を記録
2. 劣化バリエーション (微小チルト・照明ムラ・デフォーカス・ノイズ・JPEG・スケール違い) の追加
3. ここで得た限界値をもって寸法確定 (紙プロトタイプ実証の本来の目的)

# カメラ認識パイプライン — 写真 1 枚から実物回路をネットリスト化する方式

公開日: 2026-07-24。本文書は e-block-nano の認識方式の技術説明であり、
方式の先行技術化 (defensive publication) を兼ねる。ここに記載の方式・構成の
組み合わせは本プロジェクトにより公開された。

## 概要

グリッド状のベース基板に置かれた回路ブロック (各ブロック天面に 2D コードタグ) を
スマートフォンカメラで 1 枚撮影し、以下のパイプラインで**実物回路のネットリスト**を
自動構成する。

```text
写真 (斜めでも可)
  │ 1. 四隅の ArUco マーカー検出 (互いに異なる ID の 4 個)
  ▼
ホモグラフィ算出 → 真上視点に整流 (rectify)
  │ 2. 既知のグリッド座標で各セルを切り出し
  ▼
セルごとにタグをデコード (AprilTag 36h11)
  │ 3. タグ ID → 部品種、タグの回転 → ブロックの向き
  ▼
配置リスト { partId, cell(row,col), orientation }
  │ 4. グリッド隣接関係から辺共有ノードを併合 (union-find)
  ▼
ネットリスト (nets + elements + ground) → シミュレーション / 診断 / AR
```

## 方式の要点

### 1. 整流してからセル単位で読む

タグ検出を画像全体に対して行うのではなく、**先に四隅マーカーで盤面を真上視点に
整流し、グリッド座標で確定するセル領域を切り出してから**セル内のタグをデコードする。
これにより斜め撮影でも小さいタグ (5〜8mm) が安定して読める。

### 2. タグ ID は部品種のみを符号化する

セル位置は四隅マーカーからの座標計算で確定するため、タグに位置情報を持たせる
必要がない。タグ ID は**部品種 (part type + ブロック内部配線パターン) だけ**を表し、
**ブロックの向きはタグ自体の回転 (0/90/180/270°) から取得**する。
これにより必要 ID 数が部品種数で済み、小さな辞書 (AprilTag 36h11: 587 ID) で足りる。

### 3. 接点は辺中央、ノードは辺共有

ブロックの電気接点はセルの**四隅ではなく 4 辺の中央**に置く。隣接セルは境界辺を
共有するため、「同じ辺 = 同じ回路ノード」としてグリッド隣接関係から機械的に
ネットリストを構成できる (実装は [src/core/netlist/build.ts](../src/core/netlist/build.ts):
辺キー割り当て → 部品内部配線グループの union-find 併合)。
四隅接点だと格子点ノードが最大 4 ブロックで共有され、辺単位の回路意味論が崩れる。

### 4. タグファミリの選定

- セルタグ: **AprilTag 36h11** (印刷領域 ≥8mm)。5〜6mm まで詰める場合は ArUco 4x4_250
- 四隅フィデューシャル: **互いに異なる ID の ArUco 4 個** (セルタグと辞書を分けて
  誤対応を防ぐ)。QR の finder pattern 流用ではなくマーカー ID で四隅の対応を確定する
- 誤読耐性を最優先する (1 タグの誤読が回路図全体を偽にするため、ハミング距離の
  大きい辞書を部品種数に対して余裕をもって使う)

### 5. 二層コーディング (個体管理)

- **天面 = AprilTag**: 部品種。毎フレームの一括認識用
- **側面 = Data Matrix**: 個体シリアル。低頻度の接写スキャン用
- コードにはシリアルのみを持たせ、ロット・製造日・検査結果はシリアルをキーに
  DB 側で管理する (GS1/SGTIN の考え方)

## 実装との対応

| パイプライン段階 | 実装 |
| --- | --- |
| 配置 → ネットリスト | [src/core/netlist/build.ts](../src/core/netlist/build.ts) (カメラ認識も同じ `Placement` 型を出力する) |
| 部品種の定義 | [src/core/parts/catalog.ts](../src/core/parts/catalog.ts) |
| 部品種 ↔ タグ ID の正準割当 | [tools/paper-proto-gen/tag_assignment.json](../tools/paper-proto-gen/tag_assignment.json) |
| 検証用の合成画像生成 | [tools/paper-proto-gen/](../tools/paper-proto-gen/) (盤面ファイル → 真上撮影相当の画像 + 正解データ) |

オンスクリーンエディタとカメラ認識は同一の `Placement` / `Netlist` 契約に合流する。
グリッド配置エディタは「認識済みネットリスト」の代替入力であり、認識パイプラインが
完成しても netlist 以降のレイヤは変更なしで動く。
